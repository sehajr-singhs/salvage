Every dead device is a parts bin.

Salvage looks inside broken electronics, finds the parts that still work, and won't call a part good until the evidence says so. Then it gives them away.

See the systemView the code
SalvageTeardown agent

A drone with a cracked frame still has four good motors, a camera and a battery. Vision models can name those parts now, and they're usually right. Usually isn't good enough when a wrong label means a dead motor in your next build, or a swollen lithium cell in someone's hands. So a label has to be earned.

Systemsrc/salvage

The whole pipeline, and where the open model plugs in.

Every box is a folder in the repo. Every model sits behind one provider config, so moving a reader from a hosted API to open weights on your own GPU is a one-line change. Nothing after the readers is a model.

Classifygate/decide.py

Four states, checked in order. Only one of them is good.

The gate runs top to bottom and stops at the first state that applies. A part only reaches VERIFIED by passing everything above it.

01

HAZARD

Swollen lithium cells, CRT and flyback circuits, microwave high voltage, mains primaries. Checked first. Wins over everything.

02

ABSTAIN

Fewer than two readers, agreement under two thirds, readers contradicting each other, or a marking that doesn't fit the part family.

03

MEASURE

The readers agree, but a ten-second meter check would settle it. It says what to measure and the range to expect.

04

VERIFIED

The readers agree, and the measurement landed in range or the part doesn't need one.

Interfacesalvage.web

One screen. Every part, every verdict.

LoopGive, don't sell

Verified parts go back to people who'll build with them.

The Buy Nothing idea is simple: neighbors give things away instead of throwing them out. Electronics are where it breaks down, because nobody wants a "probably works" motor from a stranger. A verified label fixes that.

RoadmapHow it gets built

One bench, then one neighborhood, then a warehouse.

P0

The bench tool

Segment, read, gate, measure, inventory. A web UI and a CLI, running offline against mocks and cached answers.

Built
P1

Live models, real devices

Connect the providers, tear down real dead devices, hand-label every part, and publish coverage versus error: how many parts it labels, and how often a label is wrong.

Next
P2

Hands in the device

Voice input so you can read the meter out loud, and a foreman model that plans the teardown step by step.

Planned
P3

A neighborhood drop-off

One school or makerspace bin. Dead devices in, verified parts listed free, hazards to a recycler. Count how many parts get reused.

Planned
P4

Robot teardown cell

A robot arm does the disassembly and the same gate decides. The gate doesn't change, only the hands do.

Later
P5

The reliability record

Failure data across thousands of devices, shared with the people who design the next ones so they last longer.

Later
StatusWhere it stands

Built end to end. Tested offline. Live runs next.

Done

Segmentation, multi-model readers with an agreement signal, the gate, the measurement dialogue, inventory with reverse search, a CLI, the web UI and an evaluation harness. 232 tests pass.

Not yet

Every model call has only run against mocks and cached answers, since no API keys are connected. There are no real accuracy numbers yet, and this page doesn't claim any.
