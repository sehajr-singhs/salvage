Every dead device is a parts bin.

Salvage looks inside broken electronics, works out which parts still work, and won't call a part good until the evidence says so. Parts that pass go back into the community for free. Everything else is marked unknown or unsafe, out loud.

01 · Why

A model that's confidently wrong about a part is worse than no model.

A drone with a cracked frame still has four good motors, an ESC, a camera and a battery. You only find that out after an hour with a multimeter. Vision models can name parts from a photo now, and they're usually right. "Usually" is the problem. Call a dead motor good and someone loses an afternoon. Call a swollen lithium cell good and someone gets hurt.

So Salvage runs on one rule: a label has to be earned. Several models have to agree, the agreement has to survive plain-code checks, and anything a meter can settle gets measured.

The whole pipeline, and where the open model plugs in.

Eyes
SAM 3.1

Finds and outlines every part from text prompts. Runs through the Meta API, or the open weights on a GPU.

Readers
Several model families

Each reader names the part, reads markings and quotes the evidence it sees. Different families make different mistakes, so their errors don't line up.

Open weights
Swap in, one line

Muse Spark Open and Muse Glimmer run on your own hardware or partner inference through the same OpenAI-compatible interface. Nothing downstream changes.

Gate
Plain code

A rule table decides the final state. A model can talk itself into an answer. A rule table can't.

03 · How it classifies

Four states, checked in order. A part only gets the good one by earning it.

01
HAZARD

Swollen lithium cells, CRT and flyback circuits, microwave high voltage, mains primaries. Checked first. Wins over everything.

02
ABSTAIN

Fewer than two readers, agreement under two thirds, readers contradicting each other, or a marking that doesn't fit the part family.

03
NEEDS_MEASUREMENT

The readers agree, but a ten-second meter check would settle it. It tells you what to measure and the range to expect.

04
VERIFIED

The readers agree, and the measurement landed in range or the part doesn't need one.

04 · The loop

Give, don't sell. Verified parts go back to people who'll build with them.

The Buy Nothing idea is simple: neighbors give things away instead of throwing them out. Electronics are where that breaks down, because nobody wants a "probably works" motor from a stranger. A verified label fixes that. If Salvage has proved a part works, it's worth giving, and it's worth taking.

People
Free parts, with proof

Makers, robotics teams and schools get motors, fans, cells and boards that a gate has signed off on, not a mystery bag.

Safety
Hazards never ship

Swollen cells and high-voltage parts go to a certified recycler, never to a person.

Data
What actually fails

Every verdict is a data point on which component died first. At scale, that's a reliability map nobody else has.

05 · How it gets built

One bench, then one neighborhood, then a warehouse.

P0

The bench tool

Segment, read, gate, measure, inventory. A web UI and a CLI. Runs offline against mocks and cached answers.

Built
P1

Live models, real devices

Connect the providers, tear down real dead devices, hand-label every part, and publish coverage versus error: how many parts it labels, and how often a label is wrong.

Next
P2

Hands in the device

Voice input so you can read the meter out loud, and a foreman model that plans the teardown step by step instead of a fixed pipeline.

Planned
P3

A neighborhood drop-off

One school or makerspace bin. Dead devices in, verified parts listed free, hazards to a recycler. Measure how many parts actually get reused.

Planned
P4

Robot teardown cell

A robot arm does the disassembly and the same gate decides. The gate doesn't change, only the hands do.

Later
P5

The reliability record

Failure data across thousands of devices, shared with the people who design the next ones so they last longer.

Later
06 · Status

Built end to end and tested offline. Live model runs are next.

  • Done: segmentation, multi-model readers with an agreement signal, the gate, the measurement dialogue, the inventory with reverse search, a CLI, the web UI and an evaluation harness. 232 tests pass.
  • Not yet: every model call has only run against mocks and cached answers, because no API keys are connected. The model IDs in the config still need checking against the providers' live model lists. There are no real accuracy numbers yet, and this page doesn't claim any.
