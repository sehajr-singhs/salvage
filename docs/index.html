Teardown agent · Prove it before you label it

Every dead device is a parts bin.

Salvage looks inside broken electronics, works out which parts are still good, and refuses to call a part good until the evidence says so. When it isn't sure, it asks for one cheap measurement instead of guessing.

View the codeHow it works

01 · Why

A model that's confidently wrong about a part is worse than no model.

I build things out of dead electronics. A drone with a cracked frame still has four good motors, an ESC, a camera and a battery, but you only find that out after an hour with a multimeter. Vision models can name parts from a photo now, and they're usually right. "Usually" is the problem. If a model calls a dead motor good, you wire it into your next build and lose an afternoon. If it calls a swollen lithium cell good, someone gets hurt.

So Salvage is built around one rule: a label has to be earned. Several models have to agree, the agreement has to survive plain-code checks, and anything that can be settled with a meter gets measured. Everything else is marked as unknown, out loud.

02 · System

Eyes, several independent readers, a gate written in plain code, and a bench that remembers.

photo └─▶ SEGMENT SAM 3.1 masks every part, crops each one with 10% padding └─▶ READ each crop goes to several models in parallel, structured JSON back └─▶ GATE deterministic rules: HAZARD → ABSTAIN → NEEDS_MEASUREMENT → VERIFIED ├─▶ MEASURE ask for one cheap reading ("motor winding: 0.5 to 20 ohms"), re-gate └─▶ INVENTORY verified parts go on the shelf, searchable later ("12 V motor with driver")
Eyes
SAM 3.1

Meta's segmentation model finds and outlines every part from text prompts like "electrolytic capacitor". Runs through the Meta Model API, or the open weights on a GPU.

Readers
Muse Spark · Muse Spark Open · Muse Glimmer · a non-Meta model

Each reader names the part, reads its markings, rates its condition and quotes the evidence it actually sees. Mixing model families means their mistakes don't line up.

Gate
Plain code, no model

Decides the final state from the readers' votes, hazard rules, consistency checks and any measurement. It's deterministic and testable line by line.

Bench
Inventory + reverse search

Verified parts are stored with their ratings. Ask for what you need and it searches your own shelf first, and never returns a hazard or an unknown part.

03 · The gate

Four states. A part only gets the good one by earning it.

HAZARD

Swollen lithium cells, CRT and flyback circuits, microwave high-voltage parts, mains primary sides. Checked first, wins over everything, and the verdict says what to do instead.

ABSTAIN

Fewer than two readers, agreement below two thirds, readers contradicting each other on whether it works, or a marking that doesn't fit the part family. It says "I don't know."

NEEDS_MEASUREMENT

The readers agree, but a cheap check would settle it: motor winding resistance, cell voltage, fan spin, fuse continuity, capacitor ESR. It tells you exactly what to measure and the range to expect.

VERIFIED

The readers agree, and either the measurement landed in range or the part doesn't need one.

04 · Why this architecture

Every choice trades a little coverage for a lot of trust.

  • Disagreement is a signal, not noise. One model's confidence score says little about whether it's right. Independent models disagreeing about a part is a much better warning sign, so the readers vote and the gate counts.
  • The final call is plain code, not another model. A model can talk itself into an answer. A rule table can't, and every decision can be traced to a line and tested.
  • Measurement beats more inference. When a part is uncertain, one ten-second meter reading settles it better than asking a bigger model. The system is built to ask for that reading.
  • Hazards are checked before anything else. Being cautious is cheap. Being wrong about a lithium cell isn't.
  • Abstaining is a valid answer. The evaluation measures how much a confident wrong label costs, not just accuracy, so "I don't know" is never punished.
  • Every model call is cached and every network call can fail safely. Re-running the same photo costs nothing, and a provider timing out removes one vote instead of crashing the run.

05 · Status

Built end to end and tested offline. Live model runs are next.

  • Done: segmentation, multi-model readers with an agreement signal, the gate, the measurement dialogue, the inventory with reverse search, a command line, the web interface and an evaluation harness. 232 tests pass.
  • Not yet: every model call has only run against mocks and cached answers so far, because no API keys are connected. The provider settings follow Meta's published API, but the model IDs still need to be confirmed against the live model list.
  • Next: real runs on dead devices, a hand-labeled set of parts to score coverage against error, voice input so your hands can stay inside the device, and a foreman model that plans the teardown instead of a fixed pipeline.
